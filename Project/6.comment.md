# Brief Description of the Comments Module

The Comments module in VABRO is a reusable collaboration feature that allows users to communicate, ask questions, provide clarification, and discuss on a specific work with other workspace member within same workspace.

For example, if a tester raises a bug on a Task and the developer does not understand the issue, the developer can add a comment to that Task and mention the tester. The tester can then reply and clarify the issue. This keeps the entire discussion connected to that particular work item.


## Where Can We Use Comments?

The Comments functionality is not limited to one particular screen. The functionality is used in different artifacts of VABRO, such as:

Project — discuss project-related information.
Epic — discuss requirements or progress related to an epic.
User Story — clarify requirements or acceptance criteria.
Task — discuss implementation issues or bugs.
Sprint — discuss sprint-related work.
Release — discuss release-related information.
Scrum Board — users can access comments related to the work items shown on the board.
Kanban Board — users can open comments from a task card and discuss that particular task.
Kanban Task/User Story — discuss issues or requirements related to that specific work item.

## How We Create a Comment Using Tiptap

For creating a comment, we use a reusable **CommentForm** component. Inside the form, we use **Tiptap** as the rich-text editor.

The editor allows the user to enter formatted text and also supports **@mentions**.

The CommentForm also provides an **attachment option**, so users can attach files along with their comments.

### Component Structure

```text
CommentForm
│
├── Tiptap Editor
│     ├── Text Formatting
│     └── @Mention
│
├── AttachmentUploader
│
└── Submit Button
```

### 1. Tiptap Editor

When the user opens the comment section and click on comment, the CommentForm displays the Tiptap editor.

The user can type something like:

```text
Can you please check this issue @John?
```

We maintain the editor content in React state.

```text
User types
    ↓
Tiptap Editor
    ↓
React state
    ↓
Comment content
```

Tiptap is responsible for handling the rich-text editing experience.

---

## 2. Handling @Mentions

We use Tiptap's **Mention extension** for the `@` mention functionality.

When the user types:

```text
@Jo
```

we detect the mention and show matching users.

For example:

```text
@Jo

----------------
John
Joseph
Jonathan
----------------
```

When the user selects John, the editor displays:

```text
Can you please check this issue @John?
```

But internally, we also keep the selected user's ID.

For example:

```text
User:
id   = 25
name = John
```

So when submitting the comment, we can send:

```js
{
    content: "Can you please check this issue @John?",
    mentionedUsers: [25]
}
```

This is important because the backend needs the **user ID** to identify exactly which user was mentioned.

### Mention Flow

```text
User types @
      ↓
Tiptap detects mention
      ↓
Get text after @
      ↓
Search/filter users
      ↓
Show user suggestions
      ↓
User selects a user
      ↓
Insert mention into Tiptap
      ↓
Store selected user ID
```

---

## 3. Handling File Attachments

File uploading is handled separately from the Tiptap editor.

We provide an attachment button along with the editor:

```text
+--------------------------------------+
| Can you check this issue @John?      |
|                                      |
+--------------------------------------+

📎 Attach File                 Submit
```

When the user clicks **Attach File**:

```text
Click Attach
      ↓
File Picker
      ↓
User selects file
      ↓
React receives File object
      ↓
Validate file
      ↓
Upload using REST API
      ↓
Backend stores file
      ↓
Attachment ID returned
```

In React, we can maintain the selected file:

```js
const [file, setFile] = useState(null);

const handleFileChange = (event) => {
    setFile(event.target.files[0]);
};
```

We can then upload the file using `FormData`:

```js
const formData = new FormData();

formData.append("file", file);
formData.append("referenceType", "Comment");
```

The backend handles the actual file storage and returns the attachment information.

---

## 4. Creating the Final Comment

When the user clicks **Submit**, we combine:

* Comment content from Tiptap
* Mentioned user IDs
* Artifact information
* Attachment information

For example:

```js
{
    referenceType: "Task",
    referenceId: 501,
    content: "Can you please check this issue @John?",
    mentionedUsers: [25],
    attachments: [101]
}
```

Here:

```text
referenceType = Task
referenceId   = 501
```

means that the comment belongs to **Task 501**.

## Interview Answer

> **"For creating comments, we used a reusable CommentForm component and used Tiptap as the rich-text editor. Tiptap handles the comment content and we use its Mention extension for the @mention functionality. When the user types @, we show matching users, and after selecting a user, we store the user's ID along with the mention.**
>
> **For attachments, we handle file selection separately in React. The user selects a file, we validate it, and upload it to the backend using FormData and a REST API. Once the backend returns the attachment information, we associate it with the comment.**
>
> **When the user submits the comment, we send the Tiptap content, mentioned user IDs, attachment information, and the artifact information such as reference type and reference ID to the backend. After the API successfully creates the comment, we update React state or Redux and display the new comment in the CommentList."**

### One-line explanation

> **"Tiptap handles the rich-text and @mention experience, React handles the comment state and file selection, and the REST API handles saving the comment and attachments."**

##How update UI after adding a new comment?
 For the comment creation flow, we can use React's useOptimistic hook to provide an immediate UI response. When the user submits a comment, I optimistically add the comment to the comment list before the API finishes. This makes the UI feel faster. If the API succeeds, the comment remains and is synchronized with the server response. If the API fails, I roll back the optimistic update and show an error message to the user
