## How I Built Vabro Genie AI (React Frontend)

"I worked on Vabro Genie — the AI-powered assistant inside Vabro's project management platform. It helps teams auto-generate project structures from templates, suggests tasks using AI, generates OKRs, and provides inline AI chat. I built the React frontend that integrates with a .NET backend, which routes prompts to multiple LLM providers like OpenAI, Gemini, Claude, and Grok based on the user's subscription."

##  How to Explain the Architecture
High-Level Architecture
"We followed a decoupled architecture — React SPA on the frontend communicating with a .NET Core Web API backend. For the AI features, the backend acts as an LLM gateway that routes requests to the right AI provider based on the user's subscription tier."

## AI Task Suggestions
"When a user is on a User Story page, they can click 'Suggest Tasks using Vabro Genie AI'. I built the prompt construction on the frontend — I collect the project name, user story title, description, and existing task names from the DOM, then construct a natural language prompt with an embedded JSON Schema that tells the LLM exactly what structure to return."

## How to explain the prompt engineering:

"I used a technique called schema-constrained generation — I append a strict JSON Schema to the prompt asking for an array of 5 tasks, each with name (max 50 chars), description (max 200 chars), categories (max 3), and an estimate. This ensures the LLM returns structured data I can parse reliably."

"The response goes through a parsing pipeline — I strip markdown code fences if present, parse the JSON, deduplicate against existing task names, and render the results in a selection modal with checkboxes."

"After the user selects tasks, I create them sequentially — not in parallel — because each task creation depends on the previous one completing. I use a recursive function pattern: createTask() creates one task, and on success, calls itself for the next. After all tasks are created, I batch-update additional details (categories, estimates) with a progress bar."

## Sequential Task Creation Without Race Conditions
"When the user selects 10 AI-generated tasks, I can't create them all in parallel because the backend validates uniqueness and order. I implemented a recursive sequential pattern — createTask() processes one task, waits for the response, updates the UI (spinner → checkmark), then calls itself for the next. This avoids race conditions but created a UX challenge — users had to wait. I solved this with a progress modal showing a Genie animation and a real-time progress bar that updates after each task completes."

I used a fire-and-continue error strategy. The .finally() callback ensures the chain never breaks — if task 3 fails, it shows a red error icon on that row, skips its additional detail updates, and immediately moves to task 4. This way the user gets 4 out of 5 tasks instead of losing everything. Failed tasks simply don't appear after the page reloads."


# JavaScript Task Progression with Axios

This JavaScript example recursively processes a list of tasks **one by one**, tracks the progress, and displays the status in the console.

## Code

```javascript
import axios from 'axios';

const myTasks = [
  { name: "Task 1: Initialize Database" },
  { name: "Task 2: Seed Mock Data" },
  { name: "Task 3: Run Migrations" },
  { name: "Task 4: Clear Cache" },
  { name: "Task 5: Warm Up Services" }
];

/**
 * Recursively creates tasks one by one and tracks progression.
 */
async function runNextTask(tasksArray, currentIndex = 0) {
  const totalTasks = tasksArray.length;

  // Base Case: Stop recursion when done
  if (currentIndex >= totalTasks) {
    console.log(`\n🏁 [100%] All ${totalTasks} tasks processed successfully!`);
    return;
  }

  const currentTask = tasksArray[currentIndex];

  // 1. Calculate progression details
  const currentProgress = currentIndex + 1;
  const percentage = Math.round(
    (currentProgress / totalTasks) * 100
  );

  // 2. Create a visual progress bar
  const barLength = 10;

  const filledLength = Math.round(
    (currentProgress / totalTasks) * barLength
  );

  const progressBar =
    "■".repeat(filledLength) +
    "□".repeat(barLength - filledLength);

  // Print current progression status
  console.log(`--------------------------------------------------`);
  console.log(
    `📊 Progress: [${progressBar}] ${percentage}% (${currentProgress}/${totalTasks})`
  );
  console.log(`⏳ Starting: "${currentTask.name}"`);

  try {
    const response = await axios.post('/api/tasks', currentTask);

    console.log(`✅ Finished: "${currentTask.name}"`);
  } catch (error) {
    console.error(
      `❌ Failed: "${currentTask.name}" | Error: ${error.message}`
    );
  } finally {
    // Irrespective of outcome, move to the next task
    await runNextTask(tasksArray, currentIndex + 1);
  }
}

// Start the sequence
runNextTask(myTasks, 0);
```

## How the Progression Works

The function processes each task **sequentially**:

1. Gets the current task.
2. Calculates the current progress percentage.
3. Displays a progress bar.
4. Sends the task to the API using `axios.post()`.
5. Displays either success or failure.
6. Moves recursively to the next task.
7. Stops when all tasks are processed.

## Important Note

The `finally` block ensures that the next task is processed **whether the current task succeeds or fails**:

```javascript
finally {
  await runNextTask(tasksArray, currentIndex + 1);
}
```

So, even if **Task 2 fails**, the function continues with **Task 3** instead of stopping the entire process.

## Progress Calculation

For 5 tasks:

```text
Task 1 → 1 / 5 × 100 = 20%
Task 2 → 2 / 5 × 100 = 40%
Task 3 → 3 / 5 × 100 = 60%
Task 4 → 4 / 5 × 100 = 80%
Task 5 → 5 / 5 × 100 = 100%
```

This approach is useful when you need to execute **multiple API operations sequentially while tracking overall progress**.
